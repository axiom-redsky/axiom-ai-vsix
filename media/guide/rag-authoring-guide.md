# Axiom AI · RAG 지식 파일 작성 가이드

이 문서는 **추가 RAG 지식**을 직접 작성·등록하려는 사용자를 위한 가이드입니다.
(Scaffold 관련 내장 지식은 이미 포함되어 있으므로 다시 작성할 필요가 없습니다. 여기서는 **프로젝트/업무 고유의 지식**만 다룹니다.)

---

## 1. RAG가 무엇이고, 왜 등록하나요?

Axiom AI는 질문을 받으면 **관련 지식 문서(.md)** 를 찾아 프롬프트에 함께 실어 답합니다.
내장 지식만으로는 답할 수 없는 **우리 프로젝트만의 규칙**(예: 사내 API 응답 규약, 도메인 용어,
팀 코딩 컨벤션, 특정 화면 패턴)을 `.md` 파일로 적어 등록하면, AI가 그 내용을 근거로 답하게 됩니다.

> 핵심: **문서로 적어두지 않은 지식은 AI가 알 수 없습니다.** 알려주고 싶은 만큼만 문서로 만들면 됩니다.

---

## 2. 등록하는 두 가지 방법

설정 화면의 **RAG 지식 파일 관리**에서:

| 방법 | 언제 쓰나 | 동작 |
| --- | --- | --- |
| **폴더 선택** | 지식 문서가 여러 개일 때 (권장) | 폴더 안의 **모든 `.md`** 가 인덱스에 포함됩니다. 하위 폴더도 재귀 포함. |
| **+ 파일 추가** | 문서가 한두 개일 때 | 지정한 개별 `.md` 파일만 포함됩니다. |

폴더 방식이 관리하기 쉽습니다. 한 폴더를 정해두고 그 안에 문서를 계속 추가하세요.

---

## 3. 파일 형식 — 가장 중요한 규칙

각 `.md` 파일은 맨 위에 **frontmatter**(YAML 머리말)를 두고, 그 아래 본문을 마크다운으로 적습니다.

```markdown
---
title: 사내 API 응답 규약
category: api
tags: [api응답, response, 공통응답, resultcode, 에러코드, 페이로드, payload]
---

# 사내 API 응답 규약

모든 API는 아래 공통 봉투(envelope) 형태로 응답한다.

## 성공 응답
\`\`\`json
{ "resultCode": "0000", "message": "OK", "data": { ... } }
\`\`\`

## 에러 응답
- `resultCode` 가 `"0000"` 이 아니면 실패다.
- 화면에는 `message` 를 그대로 노출하지 않고, 코드별 안내 문구로 변환한다.
```

### frontmatter 필수 필드 (3개)

| 필드 | 의미 | 예 |
| --- | --- | --- |
| `title` | 문서 제목 | `사내 API 응답 규약` |
| `category` | 분류 (자유롭게 정함) | `api`, `convention`, `domain`, `layout` |
| `tags` | **검색 키워드 목록** (가장 중요) | `[api응답, response, 공통응답]` |

> ⚠️ **세 필드 중 하나라도 빠지면**, 그 파일은 의미 검색에는 잡히지만 **키워드 검색에서는 제외**됩니다.
> (등록은 되지만 정확도가 떨어집니다. 가급적 세 필드를 모두 채우세요.)

---

## 4. `tags` 를 잘 쓰는 법 (정확도의 핵심)

AI는 사용자의 질문에 들어있는 단어와 `tags` 를 비교해 문서를 찾습니다.
따라서 **사용자가 그 문서를 찾을 때 입력할 법한 단어를 최대한 많이** 넣어야 합니다.

- **한글 + 영어를 함께**: `[api응답, response, api response]`
- **동의어·표기변형을 함께**: `[에러코드, 오류코드, error-code, errorcode]`
- **붙여쓰기·띄어쓰기 변형**: `[공통응답, 공통 응답, 공통응답규약]`
- 너무 일반적인 단어(예: `코드`, `데이터`)만 넣으면 엉뚱한 질문에도 잡히니, **구체적인 단어** 위주로.

좋은 예:
```yaml
tags: [api응답, 공통응답, response, resultcode, 결과코드, 에러코드, 오류처리, 봉투, envelope, payload]
```

---

## 5. 본문 작성 팁

- **제목(`#`, `##`)으로 섹션을 나누세요.** 검색은 섹션 단위로 잘게 잘라 이뤄지므로, 주제별로 나누면 정확도가 올라갑니다.
- 한 섹션은 **너무 길지 않게**(대략 5~15줄). 긴 내용은 소제목으로 쪼개세요.
- **코드 예시**는 ` ``` ` 코드블록으로. AI가 그대로 참고합니다.
- "하지 말 것 / 해야 할 것"을 명확히 적으면 AI가 규칙을 더 잘 지킵니다.

---

## 6. 폴더 규칙 (폴더 방식일 때)

- 폴더 안의 **모든 `.md`** 가 포함됩니다(하위 폴더 포함).
- **파일·폴더 이름이 `_` 로 시작하면 무시**됩니다. (임시 메모를 `_draft.md` 처럼 두면 제외됨)
- 단, **`_index.md` 는 특별한 파일**입니다(아래 7번 참고).

---

## 7. (선택·고급) `_index.md` 로 키워드를 한곳에서 관리

`tags` 를 파일마다 적는 대신, 폴더 루트에 **`_index.md`** 를 두고 키워드 라우팅을 한곳에서 관리할 수 있습니다.
`_index.md` 가 있으면 **이 파일이 키워드 라우팅의 기준**이 됩니다(각 파일의 `tags` 대신).

```markdown
# 지식 인덱스

- keywords: [api응답, 공통응답, response, resultcode, 에러코드]
  files: [api/response-spec.md]
- keywords: [도메인용어, 용어집, glossary, 코드값, 공통코드]
  files: [domain/glossary.md, domain/codes.md]
```

- `keywords:` 줄과 `files:` 줄을 한 쌍으로 둡니다.
- 한 키워드 묶음이 여러 파일을 가리킬 수 있습니다.
- **`_index.md` 가 없으면** 각 파일의 `tags` 로 자동 생성되므로, 처음에는 만들지 않아도 됩니다.

---

## 8. 등록 후 확인

1. 설정에서 폴더/파일을 등록하고 저장합니다.
2. 채팅에서 그 지식과 관련된 질문을 해봅니다.
3. 잘 안 잡히면 → **`tags` 에 사용자가 쓴 단어를 추가**하고 다시 저장하세요. (가장 흔한 원인)
4. 형식 경고는 **출력 패널(View → Output → "Axiom AI")** 에서 확인할 수 있습니다.

---

## 9. 한눈에 보는 체크리스트

- [ ] 파일 맨 위에 `---` frontmatter가 있다
- [ ] `title`, `category`, `tags` 세 필드를 모두 채웠다
- [ ] `tags` 에 한글·영어·동의어를 충분히 넣었다
- [ ] 본문을 `#`/`##` 제목으로 주제별로 나눴다
- [ ] 임시 파일은 `_` 로 시작하게 이름 지어 제외했다

---

작성한 문서는 언제든 수정·추가할 수 있고, 저장하면 다음 질문부터 반영됩니다.
