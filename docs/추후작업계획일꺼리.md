## 📋 항목 1 — 관련 파일 자동 탐색 (대상 파일 해석 고도화)

**상태**: 계획 확정 · 착수 전 (0단계 측정부터 시작 권장)
**소속**: ①intent 트랙 (라우팅 = "어느 파일을 고칠지" 결정) — ②decompose 아님
**우선순위**: 중 (급한 버그 아님. 사용자 경험 개선 + CC 대비 차별화)

### 1) 왜 필요한가 (배경)

- 계기: `"getArr 함수 만들어줘"`처럼 **현재 파일에 없는 심볼**을 다룰 때, 의도(modify/create)는
  잡히지만 **대상 파일 해석**은 "열린 파일 없으면 빈손 되묻기"가 전부다.
- 현재 있는 것: ①현재 파일(자동) ②프롬프트에 `@경로`로 명시한 참조 파일 ③프롬프트에 이름이 적힌
  컴포넌트를 import 경로로 따라가기(cross-file). → **이름이 이미 나온 것만** 해석. 워크스페이스를
  뒤져 후보를 대는 일반 로직은 **없음**.
- Claude Code는 강한 모델이 Grep/Glob/Read 도구를 반복 호출해 스스로 뒤진다. **Axiom은 약한 sLLM이라
  그 루프를 못 돌린다**(슬라이스 패널 'tool' 모드 실험으로 한계 확인). → CC를 약한 모델용으로 번역해야.

### 2) 절대 원칙 (어기면 두더지잡기)

1. **"뒤지는 건 확장(결정론), 고르는 것만 모델(객관식 1회)."** 모델에 도구 반복 루프 금지.
2. **되묻기를 똑똑하게 만드는 작업이지, 추측 파일에 자동 덮어쓰기 아님.** 불확실하면 **여전히 물어본다** —
   다만 "빈손 질문" 대신 "근거 있는 후보 목록"으로.
3. **flag-gated** (`experimental.` 접두, 기본 OFF). intentClassifier 방식과 동일.
4. **측정 없는 개선 금지** — 0단계(측정)부터. speculative 구현 금지.

### 3) 3단계 접근

#### 0단계 — 측정 먼저 (권장 시작점) ⭐

- **측정 도구가 이미 있음**: IntentProbe 패널의 **"🎯 해석된 대상 파일"** 카드가 `outcome=ask-user(빈손)`을
  표시하도록 설계돼 있고, 코드 주석에도 *"대상 파일 해석 고도화(결정론 후보 수집기)가 채울 지점"*이라 명시됨.
- **할 일**: 그 패널에 **"후보 수집 드라이런"** 섹션을 얹는다. `"getArr 만들어줘"`를 넣으면 결정론 검색이
  실제로 어떤 후보를 찾아오는지(심볼/import이웃/열린탭/도메인) 눈으로 보이게. **라우팅엔 영향 0(판정만)**.
- 산출: 실사용에서 빈손 되묻기 빈도 + 후보 수집이 그중 몇 %를 근거 목록으로 바꿀 수 있나 = 착수 근거 데이터.

#### 1단계 — 결정론 후보 수집기 (모델 무관 · 위험 0)

빈손 되묻기([`_askTargetFile`](../src/providers/ChatViewProvider.ts) 진입) 직전에 후보를 긁어모아 랭킹한다.

| 소스 | 방법 | 신호 강도 |
|---|---|---|
| 심볼 정의/사용처 | `vscode.executeWorkspaceSymbolProvider('getArr')`(LSP) + 폴백 grep(`function/const/export getArr`) | 최상 |
| 현재 파일 import 이웃 | import 파싱 → `_resolveModuleToUri`(**이미 있음**) | 상 |
| 열린 탭 | `tabGroups` 스캔(비활성 포함) | 중 |
| 도메인 스코프 | intent의 `domain` 슬롯이면 그 폴더 우선 가산 | 가산 |

- 결과로 `_askTargetFile`의 QuickPick을 **"근거 있는 후보 목록"**(경로 + 근거 라벨: "정의 위치" / "import 이웃"
  / "열린 탭")으로 업그레이드. 0개면 종전대로 빈손 질문(정직하게).

#### 2단계 — 후보 여럿이면 모델 객관식 1회

- 결정론 랭킹이 애매(동률)할 때만 **region-disambiguation 패턴 재사용** — 확장이 후보 번호를 매기고
  모델이 하나 pick. 이 콜백 인프라도 **이미 있음**(`disambiguate` 콜백, runHybridRegionEdit).
- 유일 최고점이면 모델 없이 그 후보를 QuickPick 최상단에 두기만.

### 4) 가장 까다로운 설계 포인트 (처음부터 분기 설계)

**심볼이 아직 없을 수 있다.** 수집기는 두 경우를 나눠야 한다:

- 심볼이 **존재** → 그 정의 파일이 수정 대상 (modify_file)
- 심볼이 **없음** → "어디에 **만들지**" 후보 (현재 파일 / import 이웃 / 도메인 컨텍스트) — create 쪽

이 분기를 초기 설계에 넣지 않으면 나중에 modify/create 라우팅과 꼬인다.

### 5) 안전장치

- 자동 적용 절대 없음 — 후보가 아무리 강해도 **QuickPick으로 제시**(사용자 최종 확정).
- 0개·모호 → 종전 빈손/되묻기 그대로. 후보 수집은 **더 나은 되묻기**일 뿐, 새 실행 경로가 아님.
- 회귀 게이트: `test:offline-intent` · `test:region-edit`(공통 안전망) · IntentProbe 드라이런.

### 6) 재사용할 기존 인프라 (새로 안 만들어도 되는 것)

- [`_resolveTargetFile`](../src/providers/ChatViewProvider.ts) 결정 사슬 ①~⑥ (778줄~) — ⑥ 되묻기 앞에 수집기 삽입
- [`_askTargetFile`](../src/providers/ChatViewProvider.ts) (828줄) — QuickPick 되묻기 지점 = 업그레이드 대상
- `_resolveModuleToUri` — import 경로 → 파일 해석 (결정론, 이미 검증)
- region-disambiguation `disambiguate` 콜백 — 모델 객관식 pick
- IntentProbePanel `_probeTargetResolve` 미러 — 0단계 드라이런 얹을 자리
