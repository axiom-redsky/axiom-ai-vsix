1결론 요약

"Axiom 특허가 어렵다"는 결론이 아니다. "넓은 특허는 사실상 불가능하고, 좁은 특허는 충분히 가능하다"가 정확한 결론이다.

중국 문헌 CN 122195419 A를 청구항 단위로 정밀 대조한 결과, 이 문헌은 Axiom의 특허 본진(코드 적용·검증 계층)과 접촉면이 없다. 침해 리스크는 매우 낮고(all-elements 미충족 + 중국 내 효력), 3층 청구항의 인용문헌으로 쓰기도 어렵다.

반면 미국 문헌 US 2026/0133770 A1(Presidio)은 급이 다르다. "부분 편집" "검증 폐루프" 같은 넓은 표현을 정면으로 밟는다. 그러나 본진인 ②(실패모드별 결정론 교정기)는 여전히 무개시이며, "에이전트를 더 얹는가(Presidio) vs 결정론 코드를 얹는가(Axiom)"라는 구별 축이 선명하다. 넓게 쓰면 죽는다는 명제가 가설이 아니라 현실임이 확인됐고, 그에 맞춰 청구항 문구를 좁히는 개정을 9절에 반영했다.

종합 판정(8절): 특허 가능하다 — 단, ②+④ 좁힌 구성 1건 기준 조건부 60~75%. 그리고 그 1건의 생사는 기술이 아니라 공지예외 기산점이 쥐고 있다. Scaffold 단독은 특허 대상이 아니며(저작권·영업비밀 영역), 출원 단위는 "Scaffold 규약을 검증 기준으로 쓰는 Axiom 방법" 1건이 맞다. 그 1건은 Scaffold+Axiom 결합 시스템(독립항 1) + 일반화 방법(독립항 2)의 2단 독립항 구조로 설계한다(9.1절).

진짜 위험 요소는 이 문헌이 아니라 GitHub 공개에 따른 공지예외 유예기간이다. 국가별로 유예 제도가 달라 중국·유럽 출원은 이미 닫혔다고 보아야 하며, 한국의 잔여 기간 확인이 가장 급하다.

특허로 살아남을 확률이 가장 높은 부분은 StructuralAnchor 기반 리전 편집 계층이며, 그중에서도 "약한 모델 출력의 실패모드별 결정론 교정 + 검증 폐루프"가 선행기술이 가장 덜 밟은 땅이다.

2층별 진단 — 3층 구조 분석

Axiom을 세 층으로 나누면 특허성 판정이 층마다 갈린다.

1층 — 컨셉층 사실상 포기

"폐쇄망에서 로컬 LLM + 벡터DB로 코딩을 보조한다"는 층이다. Continue, Tabby, PrivateGPT 계열과 로컬 RAG 논문 다수, 그리고 이번 중국·미국 문헌까지 전부 선행기술이다. 이 층에 청구항을 걸면 거절이 확실하므로 예산과 미련을 두지 않는다.

2층 — 리트리벌 파이프라인 조건부 생존

centroid 라우팅 + RRF + reranker 게이팅. 각 요소는 전부 기성품이다(RRF는 논문 발표 후 20년 가까이 경과, reranker 게이팅도 일반적). 조합만으로는 진보성이 약하다. 다만 은행 표준단어·표준용어·표준도메인이라는 특정 데이터 구조와 결합하면 — 예: "메타데이터 필드 태깅을 라우팅 기준으로 사용" — 심사관이 인용할 수 있는 문헌이 급감한다. 넓게 쓰면 죽고, 은행 메타데이터에 묶으면 산다.

3층 — StructuralAnchor 리전 편집 특허 본진

특허 심사는 "문제 → 수단 → 효과"가 구체적으로 맞물릴 때 통과되는데, 이 층이 유일하게 세 요건을 자력으로 충족한다.

  • 문제가 구체적 — 로컬 소형 모델은 파일 전체를 다시 출력하지 못한다.
  • 수단이 구체적 — 구조적 앵커로 편집 영역을 특정해 해당 구간만 교체한다.
  • 효과가 측정 가능 — 토큰 소모, 적용률(계기판 기준 33%→84%), 컨텍스트 초과 실패율.

약 1,700줄 규모의 src/ai/apply/StructuralAnchor.ts 구현체가 그 자체로 실시 근거가 된다.

3.3 결정적 차이 — "적용(apply) 계층"의 부재

문헌 전체를 훑어도 생성된 코드를 파일에 적용하는 단계가 단 한 줄도 없다. 모델 응답은 터미널에 출력되고 끝난다(【0043】). 즉:

  • 구조적 앵커로 편집 영역을 특정하는 것 — 없음
  • 모델 출력의 실패모드를 교정하는 것 — 없음
  • tsc 검증-교정 폐루프 — 없음
  • 편집 결과의 정합성 보장 — 개념 자체가 없음

Axiom의 본진(3층: StructuralAnchor + 결정론 교정기 + verify-correct 루프)은 이 문헌과 접촉면이 0이다. "코드 조각을 생성한다"까지는 같지만, 이 특허의 세계는 생성에서 끝나고 Axiom의 세계는 생성 이후부터 시작한다.

3.4 가장 가까운 접점 — 그리고 왜 다른가

유일하게 닮은 부분은 S4의 "2차원 매칭"(키워드 매칭 실패 시 임베딩 유사도 폴백)으로, Axiom의 의도 라우팅과 표면적으로 유사하다. 그러나:

  • 목적이 다름 — 저쪽은 "OS 튜닝 도구를 부를까 말까"의 이진 트리거, Axiom은 수정/생성/질문/페이지생성 등 다중 의도 분류 후 편집 파이프라인 라우팅
  • 수단이 다름 — 저쪽은 사전 구축된 트리거 KB와의 코사인 임계값(0.9), Axiom은 LLM 위임 분류(IntentClassifier) + 정규식 폴백 + 충돌 안전 되묻기

이 접점조차 청구항 1의 다른 필수 요소(S1의 파인튜닝·GGUF)가 Axiom에 없으므로 침해 구성이 되지 않는다.

3.5 종합 판정 — 두 관점

① 침해 리스크 관점 (Axiom이 이 특허를 밟는가): 매우 낮음

  • 청구항 1의 필수 요소 S1(자체 파인튜닝+GGUF 제작)과 S4(OS 튜닝 도구 호출)를 Axiom은 수행하지 않음 → all-elements 기준 미충족
  • 중국 출원이므로 효력 범위는 중국 내 — 한국 사업에는 애초에 미치지 않음

② 선행기술 관점 (Axiom 출원 시 인용될 것인가):

  • 1층 — "로컬 경량모델 + 로컬 RAG + 구조화 프롬프트로 개발 보조"의 공지 재확인. 사망 판정 유지
  • 2층 — 일반형 RAG(milvus+ANN+스티칭)가 공지됐으니, 은행 표준 메타데이터 결합 없는 일반 청구항은 더 위험해짐
  • 3층 — 편집·적용·검증 영역에 아무 개시가 없어 인용문헌으로 쓰기 어려움. "②+④ 뼈대 + ① 환경" 전략이 이 문헌으로 오히려 지지됨
시간관계 부수사항 — 이 출원의 출원일은 2026-03-13. 만약 Axiom의 GitHub 공개가 그보다 앞선다면, 반대로 Axiom의 공개가 이 출원의 선행기술이 되는 관계다(그들의 중국 심사에서). 공지예외 기산점 확인과 함께 시간관계를 대리인에게 전달할 가치가 있다.

동기SDLC 효율·감사가능성·범위 통제약한 모델이 검증 에이전트 함대를 감당할 수 없다는 자원 제약

이 대비는 억지가 아니라 전제에서 필연으로 도출된다 — 은행 폐쇄망의 소형모델로는 비평가 LLM을 돌릴 여유가 없으니, 검증을 결정론으로 내릴 수밖에 없다. 문제→수단의 인과가 깨끗하다.

4.4 침해 리스크 — 낮음

  • 실제 청구항 1~20은 "요구사항 정의 데이터셋 → requirement data objects → code generation work prompt sets → 빌드" 파이프라인. Axiom에는 요구사항 분해·work prompt set 생성 단계 자체가 없어 all-elements 미충족.
  • 변경격리·세그먼트 수정은 청구항이 아니라 Clause(예비 청구항 후보) 67~84와 명세서에만 존재. 다만 심사 중 청구항으로 승격될 수 있으므로 추적 가치가 있다.
  • 공개 출원(A1)이며 등록특허가 아니다.

4.5 전략에 미치는 영향

  • ②가 명실상부한 최전선 — 두 문헌 모두 무개시. 집중 결론이 더 강화됨.
  • ④ 표현 좁히기 — "폐루프 검증"만으로는 밟힘. 살아남는 한정: "LLM 비평가가 아닌 결정론 컴파일러 진단 · 에디터 내 임시 형제파일 · 1회 앵커 교정 · fail-open".
  • ① 전제부 좁히기 — "부분 편집"이 아니라 "임베딩 유사도가 아닌 결정론 구조 앵커로 위치를 특정하는" 부분편집으로.
  • ⑤ 좁히기 — "규약 대조"가 아니라 "LLM 판단 없이 집합 소속 판정(폐쇄 세계)으로, 검증 데이터는 스캐폴드에서 자동 파생".
  • 신규 한정 후보 — "검증 단계에서 추가 생성형 모델 호출 없이": 이 문헌과의 가장 깨끗한 경계선을 청구항 문언으로 박제.
  • 미국 출원 시 IDS(정보개시서)에 이 문헌 필수 제출 — 알고도 미제출 시 권리행사 불능(inequitable conduct) 사유.
시간관계 부수사항 — 이 문헌의 유효 선행일은 미국에서 2024-11-12(가출원)까지 소급될 수 있고, 한국에서는 공개일 2026-05-14부터 선행기술이 된다. Axiom GitHub 공개일과의 선후 정리를 CN'419 건과 함께 대리인 전달 목록에 추가한다.

5핵심 차별 명제

차별점은 "무엇을 하느냐(what)"가 아니라 "어떻게 신뢰성을 확보하느냐(how)"에 있다. 한 문장으로 압축하면:

약한 로컬 소형모델을 신뢰 가능한 코드 편집기로 만들기 위해, "결정론(확장) / 확률(모델)"을 특정 방식으로 분업시키는 아키텍처.

Continue·Tabby·PrivateGPT 계열 선행기술은 전부 "모델에게 맡기고 결과를 받는" 구조로, 모델이 강하다는 전제 위에 서 있다. Axiom의 전제는 정반대다 — "모델은 약하다. 그러므로 모델이 하는 일을 한 조각으로 좁히고, 위치 결정·검증·교정은 확장이 결정론으로 처리한다." 이 전도된 전제가 코드 전반에 일관되게 구현되어 있으며, 이것이 선행기술과 갈라지는 지점이다. 모델을 신뢰하는 전제에서는 아래 6절의 장치들이 애초에 필요하지 않기 때문이다. US'770이 같은 신뢰성 문제를 "에이전트 추가"로 푸는 것과 정확히 대비된다(4.3절).

6청구항 재료 — 구체 기술수단 5종 + 종속항 후보 ⑥

추상 명제만으로는 청구항이 성립하지 않는다. 아래 구체 수단들이 실제 코드로 존재한다.

① 구조적 앵커 기반 부분편집

  • splitTsSections가 소스를 import / 컴포넌트 / 섹션 단위로 결정론적으로 분해하고, computeAnchors가 삽입·교체 지점을 특정한다 (StructuralAnchor.ts:287).
  • 모델은 그 안에 들어갈 조각(hookCode)만 생성한다 — 파일 전체 재출력을 요구하지 않는다.
  • "파일 전체 재출력 불가"라는 소형모델 고유 문제의 직접 해법이다.

주의: ① 단독은 완전 신규가 아니다. LSP/AST 기반 부분편집, tree-sitter 범위 편집 등의 선행기술이 존재한다. 특히 US'770의 변경격리 에이전트가 "부분 편집" 일반 표현을 공지했으므로, ①은 "임베딩 유사도가 아닌 결정론 구조 앵커" 한정을 붙여 청구항의 실행환경(전제부)으로 배치하는 것이 안전하다(9절).

② 생성물의 결정론적 사후 정합 — 가장 덜 밟힌 땅

모델 출력을 그대로 적용하지 않고, 소형모델의 전형적 실패모드를 열거한 뒤 각각에 전용 결정론 교정기를 붙였다. 이 "실패모드 열거 + 교정기" 구조는 좁은 청구항으로 쓰기에 적합하다. CN 122195419 A와 US 2026/0133770 A1(Presidio)을 포함한 검토 선행기술 어디에도 이 영역의 개시가 없다 — US'770조차 교정을 전부 LLM 에이전트에 맡긴다.

③ 트리거 기반 계약 자동주입 (ScaffoldContracts)

프로젝트 스캐폴드 특유의 계약(useApi 봉투 구조, 라우터, 타입 규약 등 11종 계약 카드)을 트리거 단어로 감지해 프롬프트에 자동 주입한다. 2층 전략의 "도메인 결합" 논리와 정확히 맞물린다 — 특정 스캐폴드/표준 구조에 묶을수록 인용문헌이 줄어든다.

④ 검증-교정 폐루프 (Verify-Correct Loop)

편집 결과를 임시 형제파일로 만들어 tsc 진단(VSCode getDiagnostics)으로 검증하고, 실패 시 앵커 기반 <replace> 교정을 1회 수행한 뒤 fail-open 한다. 선행기술의 open-loop one-shot 구조와 대비되는 폐루프(closed-loop)다.

주의: US'770이 "LLM 리뷰어 + 테스터 에이전트" 형태의 폐루프를 개시하므로, 청구항 문구는 "LLM 비평가가 아닌 결정론 컴파일러 진단 · 임시 형제파일 · 1회 앵커 교정 · fail-open"으로 좁혀야 한다(4.5절).

⑤ 스캐폴드 규약의 폐쇄 세계 오라클화 — ③을 ②·④와 묶는 접착제

업무별 격리 폴더 구조·네임스페이스·import 경로·컴포넌트 집합이 사전 정의된 스캐폴드를 "폐쇄 세계(closed world)"로 삼아, 언어모델 출력의 규약 위반을 결정론적으로 판정하고 교정하는 방법.

핵심은 "스캐폴드에 규약이 있다"가 아니라 같은 규약이 두 번 쓰인다는 점이다:

  • 사전(생성 전) — 규약을 계약카드로 프롬프트에 주입해 모델이 지키도록 유도
  • 사후(생성 후) — 동일 규약을 검증 오라클로 삼아 출력의 위반을 기계 판정·교정

일반 도구에서는 환각 import와 정상 import를 구분할 방법이 없다(열린 세계). 스캐폴드가 유효한 경로·컴포넌트·네임스페이스의 유한 집합을 사전 정의하기 때문에, 그 집합 밖의 출력 = 위반으로 결정론 판정이 가능해진다. 이것이 규약 사전 정의가 만들어내는 기술적 효과다.

주의 — "규약을 프롬프트에 주입한다"까지만 쓰면 Aider CONVENTIONS.md 계열과 정면충돌한다. 살아남는 표현은 반드시 "주입 + 동일 규약 대비 사후 검증·교정"의 결합이어야 하고, 폐쇄 세계 판정(유한 집합 밖 = 위반)이라는 기술적 효과를 명시해야 한다. 주입은 공지, 오라클화가 차별점이다.

⑥ 모델-선택적 강등 아키텍처 (오프라인 가이드) — 종속항 후보

"AI 서버 없이도 로컬 지식으로 가이드를 제공한다"는 문장 단독은 오프라인 도움말·로컬 문서검색이라는 가장 오래된 선행기술 카테고리라 독립항이 될 수 없다. 그러나 Axiom의 실제 구현은 단순 오프라인 폴백이 아니라, LLM 호출을 필수 구성이 아닌 "생략 가능한 자원"으로 취급하는 연속 강등(graceful degradation) 구조다:

단계동작실제 구현
온라인 + 지식 확신LLM 호출을 생략하고 지식문서 전문 렌더확신 게이트 (빈손·FALLBACK_HINT 아닐 때만 생략, 약하면 LLM 폴백)
온라인 + 지식 불충분LLM + RAG통상 경로
서버 불가용사전 헬스체크로 선차단 → 결정론 의도분류 + 로컬 RAG 합성 응답OfflineKnowledgeRetriever + IntentSignals, 무의미 재시도 데드엔드 제거

기존 뼈대와의 두 접점:

  • 신규 한정과 같은 계열 — "검증 단계 추가 생성형 모델 호출 없이"(8·9절)의 사상을 응답 생성으로 확장한 것. "검증에서도, 응답에서도, 모델 완전 부재 시에도 결정론이 충분하면 생성형 모델 호출을 생략한다" — US'770(에이전트 추가 방향)과의 구별축이 시스템 전체에 일관됨을 보여주는 발명 사상 통일성의 증거가 된다.
  • ⑤의 실증 — "Scaffold 규약이 기계 소비 가능한 폐쇄 세계"라는 주장에 대해, 오프라인 가이드는 그 지식이 모델 없이도 단독 동작할 만큼 자립적이라는 실증이다. "이거 프롬프트 엔지니어링 아니냐"는 SW 적격성 공격의 방어 재료.

배치: 종속항 후보 A(강등 경로 — "생성형 모델 서버가 가용하지 않은 경우, 결정론 의도 분류와 스캐폴드 규약 지식베이스 검색에 기초하여 가이드 응답을 제공"), 종속항 후보 B(확신 게이트 — "검색 확신도가 임계값 이상인 경우 생성형 모델 호출을 생략"). 명세서 효과 = 폐쇄망 서버 장애 내성(가용성)·호출 비용/지연 절감. 미래 트랙 T3("서버 없는 설치 = 1급 지식모드")가 실현되면 실시예가 두꺼워지며, 출원 시점에 실시예로 선기재 가능(대리인 판단 사항). 영업 덤: "서버가 죽어도 가이드는 산다" — 폐쇄망 가용성 스토리.

8종합 결론 — 특허 가능성 판정

"특허 가능하다. 단, '좁힌 청구항 1건'이라는 조건에서만. 그리고 그 1건의 생사는 기술이 아니라 공지예외 기산점이 쥐고 있다."

아래 확률은 법률 자문이 아니라 두 문헌 실측 대조에 근거한 기술적 판단이며, 한국 출원 기준이다. 공지예외 기산점이 확인되기 전까지는 전부 가정부(假定附) 확률이다.

8.2 왜 ②+④는 높게 보는가 — 세 가지 실측 근거

  • 두 실물 문헌이 역설적으로 증명해줬다. CN'419는 적용 계층 자체가 없고, US'770은 같은 문제를 "LLM을 더 얹어서" 푼다. 즉 이 분야의 자연스러운 발전 방향은 에이전트 추가이지 결정론 교정기가 아니다 — 통상의 기술자가 쉽게 도달하지 않는 방향이라는 진보성 논증이 문헌으로 뒷받침된다.
  • 한정이 임의적이지 않다. "추가 LLM 호출 없이"는 회피 설계용 문구가 아니라 폐쇄망 소형모델이라는 전제에서 필연으로 도출된다. 심사관 면담에서 서사가 무너지지 않는다.
  • 실시가능성·효과가 전부 실재한다. 함수 단위 코드, 재현 가능한 eval 수치. 명세서를 "주장"이 아니라 "기록"으로 쓸 수 있다.

8.3 확률을 뒤집는 세 개의 게이트

  • 공지예외 기산점 (치명적) — GitHub 공개일 기준 12개월이 지났다면 위 확률은 전부 0이 된다. 한국·일본·미국만 살아있고 중국·유럽은 이미 닫힘. 이것이 확인되기 전까지 위 표는 전부 가정부 확률이다.
  • 시간 — Presidio 문헌이 보여주듯 이 분야는 지금 빠르게 울타리가 쳐지는 중이다. 6개월 뒤에는 ②를 밟는 문헌이 나올 수 있다. 출원은 빠를수록 유리하다.
  • SW 발명 적격성 — "단순 규칙의 조합" 거절 리스크는 남는다. 하드웨어 자원 제약(폐쇄망·소형모델·컨텍스트 한계)과 결합된 기술적 효과로 서술하면 방어 가능하나, 변리사의 솜씨가 필요한 부분.

8.4 Scaffold 자체의 특허성

Scaffold(폴더 구조·규약·컴포넌트 체계) 단독은 특허 대상이 아니다. 그것은 저작권 + 영업비밀의 영역이다. Scaffold가 특허에서 의미를 갖는 건 오직 "Axiom이 그 규약을 폐쇄 세계 오라클로 소비하는 방법"(⑤)의 구성요소로서다. 즉 출원 단위는 "Scaffold 특허 + Axiom 특허" 2건이 아니라 "Scaffold 규약을 검증 기준으로 쓰는 Axiom 방법" 1건이 맞다.

보완 — 결합 시스템 청구: 이를 한 단계 발전시켜, Scaffold를 청구항 밖의 전제가 아니라 결합 시스템 청구항의 구성요소로 편입할 수 있다 — "사전 정의된 규약을 갖는 스캐폴드부 + 그 규약을 주입·검증에 공용하는 확장부를 포함하는 코드 생성 시스템". 이렇게 하면 Scaffold가 "특허 불가"가 아니라 청구항의 몸 안으로 들어오고, 상품 실체와 특허 실체가 1:1로 일치한다. 상세 설계는 9.1절.

9청구항 전략 제안 (US'770 반영 개정)

9.1 출원 골격 — Scaffold+Axiom 결합의 독립항 2단 전략

특허는 상품이 아니라 기술 구성에 걸리지만, "Scaffold와 Axiom을 하나의 상품으로 묶는" 방향은 시스템 청구항으로 정확히 구현된다. 한 출원 안에 시스템·방법·기록매체 청구항을 함께 넣는 표준 관행을 따르되, 독립항을 2단으로 쌓는다:

청구항내용역할
독립항 1 (결합 시스템)"사전 정의된 업무별 격리 폴더·네임스페이스·컴포넌트 집합 규약을 갖는 스캐폴드부 + 규약에서 자동 파생된 검증 데이터 + 앵커 부분편집·실패모드 교정기·컴파일러 폐루프를 수행하는 확장부를 포함하는 코드 생성 시스템"등록 확률 최대 — 안전한 본진. 상품과 1:1 대응
독립항 2 (일반화 방법)Axiom의 동작 방법 — 스캐폴드를 "사전 정의된 규약 집합"으로 일반화하여 기재살아남으면 더 넓은 울타리. 심사에서 죽으면 독립항 1로 후퇴
종속항들⑤ 오라클 세부 · ⑥ 강등 · ③ 카드 주입 등후퇴 지점 확보

결합의 이점 3가지:

  • Scaffold가 청구항의 몸 안으로 들어온다 — "특허 불가" 판정(8.4절)이 결합 시스템에서는 "정답지를 공급하는 구성요소"로 반전된다.
  • 결합발명 진보성 논증이 강해진다 — 검증 데이터(componentPropsIndex)가 Scaffold의 types.ts에서 자동 파생되어 Axiom의 채점에 쓰이는 상호 의존 구조 = 구성요소 간 유기적 결합관계의 실증.
  • 상품 실체 = 특허 실체 — "우리가 파는 제품 그 자체가 특허 출원 중"이라는 문장이 성립, 간판 효과 극대화.

트레이드오프: 결합 청구항은 all-elements 원칙상 좁다 — 경쟁사가 스캐폴드 없이 Axiom류 도구만 만들면 독립항 1로는 못 잡는다. 그래서 독립항 2(일반화 방법)가 반드시 병행되어야 한다. 주의(단일성): "상품 전체니까" 스캐폴드 생성기·검색층·스토리북까지 넣으면 1출원 1발명 원칙 위반으로 분할 요구를 받는다. 결합의 축은 "규약 → 검증" 하나로 유지하고, 은행 검색층(2층)은 예정대로 별건. 등록 전망(8.1절 60~75%)은 이미 이 프레임 기준이므로 결합으로 확률이 더 오르는 것은 아니며, 오르는 것은 등록 후의 서사 가치와 영업 가치다.

9.2 청구항 본문의 구성 요소

  • 뼈대 = ②+④(좁힌 문구) — "약한 모델 출력의 실패모드별 결정론 교정 + 폐루프 검증". 단, ④는 "LLM 비평가가 아닌 결정론 컴파일러 진단 · 임시 형제파일 · 1회 앵커 교정 · fail-open"으로 한정해 US'770의 리뷰어/테스터 에이전트와 문언으로 구별한다.
  • ① = 실행환경(전제부)으로 배치, 결정론 앵커 한정 필수 — "로컬 소형모델 + 폐쇄망 제약 하에서, 임베딩 유사도가 아닌 결정론 구조 앵커로 편집 영역을 특정하는 시스템에 있어서…" 형태. "부분 편집" 일반 표현은 US'770 변경격리에 공지되어 위치 결정의 결정론성으로 갈라야 산다.
  • 신규 한정 = "검증 단계에서 추가 생성형 모델 호출 없이" — US'770과의 가장 깨끗한 경계선을 청구항 문언으로 박제한다. 약한 모델 전제에서 필연으로 도출되는 한정이라 명세서 서사도 자연스럽다.
  • 접착제 = ⑤ 스캐폴드 규약 오라클(좁힌 문구) — ②+④ 뼈대에 대한 심사관의 예상 반문 "검증 기준은 어디서 오는가?"에 대한 답으로 배치: "검증 기준은 사전 정의된 스캐폴드 규약(격리 폴더·네임스페이스·import 경로·컴포넌트 집합)에서 자동 파생되며, 동일 규약이 생성 전 주입과 생성 후 검증에 공용된다." 단, US'770의 '리뷰어 LLM이 코딩 표준 대조'와 구별되도록 "LLM 판단 없는 집합 소속 판정(폐쇄 세계) + 검증 데이터 자동 파생"을 문언에 명시한다. ③(ScaffoldContracts)을 ②·④와 하나의 사상으로 묶고, 은행 표준 메타데이터 결합(2층 전략)과도 같은 논리 구조라 명세서에서 일관 서술이 가능하다.
  • 종속항 = ⑥ 모델-선택적 강등 — 후보 A(서버 불가용 시 결정론 의도분류+스캐폴드 지식 검색으로 가이드 제공), 후보 B(검색 확신도 임계 이상이면 생성형 모델 호출 생략). "호출 없이" 신규 한정과 같은 축이라 청구항 세트의 일관성을 만든다.
  • 2순위 = ③ + 은행 표준 메타데이터 — 메타데이터 필드 태깅을 라우팅 기준으로 쓰는 도메인 결합형 리트리벌을 별건으로 검토한다.

10최우선 리스크 — 공지예외 유예기간

공지예외(신규성 상실의 예외) 제도는 국가마다 다르며, GitHub 공개는 이미 발생한 사실이다.

지금 당장 확인할 것 — 한국의 12개월 유예가 언제 시작됐는가. 최초 커밋 날짜 기준인지, 해당 기술(StructuralAnchor 등)이 포함된 코드가 공개된 날짜 기준인지에 따라 잔여 시간이 달라진다. 이 확인이 중국 문헌 분석보다 우선순위가 높으며, 대리인(변리사)과 즉시 확정해야 한다.

11영업(피치) 관점의 특허 포지셔닝

금융권 SI RFP에서 등록특허와 출원중의 실질 차이는 크지 않다. "특허 출원 중" 한 줄이 평가표에서 수행하는 역할은 대부분 "자체 기술 보유"의 증명이지, 경쟁사 차단이 아니다.

Continue+Ollama 조합과 경쟁할 때 실제로 이기는 무기는 특허가 아니라 은행 표준 메타데이터 파이프라인과 폐쇄망 실증 레퍼런스다. 따라서 특허는 "울타리"가 아니라 "간판"으로 기대하는 것이 현실적이며, 실질 방어의 본체는 기존 결론대로 영업비밀 + EULA 강화다. 특허는 그 위에 얹는 신뢰 장치다.

12액션 아이템

  1. 공지예외 잔여기간 즉시 확인 — GitHub 공개 시점 기산을 대리인과 확정. 모든 전략이 이 답에 종속된다. (최우선)
  2. 컨셉층(1층) 청구항 폐기 — 예산과 미련을 두지 않는다.
  3. 결합 시스템(독립항 1) + 일반화 방법(독립항 2)의 2단 구조로 1건 제대로 출원 — ②+④(좁힌 문구) 뼈대 + ①(결정론 앵커 한정) 실행환경, "검증 단계 추가 생성형 모델 호출 없이" 한정 포함. Scaffold는 독립항 1의 구성요소로 편입(9.1절).
  4. 은행 메타데이터 RAG(②층+③)는 도메인 결합형으로 2순위 별건 검토.
  5. 두 문헌과의 시간관계를 대리인에게 전달 — CN'419 출원일 2026-03-13 · US'770 유효 선행일 2024-11-12 소급 가능 vs Axiom GitHub 공개일의 선후 확인.
  6. 미국 출원 시 IDS(정보개시서)에 US'770 필수 제출 — 알고도 미제출 시 권리행사 불능 사유. Clause 67~84의 청구항 승격 여부도 추적.
  7. 방어 본체는 영업비밀 + 계약(EULA) 유지 — 특허는 간판으로 운용.
